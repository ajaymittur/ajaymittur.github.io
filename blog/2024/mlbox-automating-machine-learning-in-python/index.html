Machine learning (ML) models are very powerful and have been used to solve a wide range of problems in the industry. However, in reality, ML systems are much more than the models that encapsulate them. Building and deploying ML models can become a complex and time-consuming process. This is where AutoML comes in.

AutoML is a field of machine learning that automates the process of building production ML systems, which includes tasks such as data preprocessing, feature engineering, model selection, and hyperparameter tuning.

What is MLBox?

MLBox is a powerful Automated Machine Learning python library. It provides the following features:

  • Fast reading and distributed data preprocessing/cleaning/formatting.
  • Highly robust feature selection and leak detection.
  • Accurate hyper-parameter optimization in high-dimensional space.
  • State-of-the art predictive models for classification and regression (Deep Learning, Stacking, LightGBM,…).
  • Prediction with models interpretation.

More info on the library can be found on their wiki. Home — Welcome to MLBox’s official documentation — MLBox Documentation

It has done really well in Kaggle competitions like Two Sigma Connect: Rental Listing Inquiries | Kaggle (rank 85/2488) and Sberbank Russian Housing Market | Kaggle (rank 190/3274) demonstrating its efficacy

The library aims to abstract away all the tedious work of data munging, wrangling, modeling, etc. so that engineers can build solutions quickly and even people with less experience in ML can develop ML applications.

Trying it Out

To explore MLBox’s capabilities, let’s build an ML pipeline to predict a movie’s popularity. I will be using the dataset from Kaggle’s Movie Popularity Prediction | Kaggle competition for this.

Installation

Installing MLBox is pretty easy, with a few extra steps if you’re on MacOS:

  1. Clone the git repository
    git clone https://github.com/AxeldeRomblay/MLBox.git
  2. Install setuptools and wheel
    pip install setuptools wheel
  3. Install OpenMP and HDF5 (only needed for MacOS)
    brew install libomp hdf5
  4. Build the repository
    pip install .
    And that should be it, you may run into versioning errors, if that's the case, following the instructions in this issue should fix it. Installation Error · Issue #147 · AxeldeRomblay/MLBox · GitHub

Removing and Updating Deprecated Code

Because the library hasn’t been updated in over 4 years, it hasn’t really kept up with the evolving landscape of its dependencies. Hence, you are going to have to manually remove deprecated pieces of code or update them in order to get MLBox to work. I had to:

  • Update pd.read_csv signature in the Reader class to
class Reader(): 
...
  def clean(self, path, drop_duplicate=False): 
      df = pd.read_csv(path,                                    
                       sep=self.sep,                                    
                       header=self.header,
                       engine='c',                                    
                       on_bad_lines='warn')
...
  • Define SCORERS in Optimizer with get_scorer_names()
    - SCORERShas been deprecated in newer versions of scikit-learn
  • Remove all instances of pd.SparseDataFrame in regressor.py
    - It’s been replaced with newer data structures in pandas. Sparse data structures — pandas 2.2.1 documentation

Dataset

Once all that’s done, we can finally use MLBox like how it was meant to be used. However, it does not support complex data types in dataframes like lists, and dictionaries. Hence, we need to get rid of those columns in the dataset.

Read the dataset and remove columns containing complex data types

def read_df(path):
    df = pd.read_csv(path, index_col=0)
    columns_to_remove = ['genres', 'production_companies', 'production_countries', 'spoken_languages', 'keywords']
    df = df.drop(columns_to_remove, axis=1)
    return df

Finally, you’ll want to save this dataset to be read by MLBox

# Read
train_df = read_df('movies_train.csv')
test_df = read_df('movies_test.csv')
# Write
train_df.to_csv('train.csv', index=False)
test_df.to_csv('test.csv', index=False)

MLBox

First, import MLBox

from mlbox.preprocessing import *
from mlbox.optimisation import *
from mlbox.prediction import *

Then let’s read the dataset using Reader which provides some handy abstractions such as train_test_split and clean. We use the train_test_split method directly which given a list of several paths and a target name, automatically creates and cleans train and test datasets. Keep in mind that the test dataset should not have a target column.

paths = ['train.csv', 'test.csv']
target_name = 'popularity'
data = Reader(sep=",").train_test_split(paths, target_name)

As you can see, it automatically encodes categorical columns, imputes missing values, fits and predicts a model with cross validation. In this case LightGBM

You can also automatically perform the best hyperparameter search. The hyperparameter syntax closely follows scikit-learns syntax for GridSearch or RandomSearch, presumably because it uses scikit-learn under the hood.

space = {
        'ne__numerical_strategy' : {"space" : [0, 'mean']},
        'ce__strategy' : {"space" : ["label_encoding", "random_projection", "entity_embedding"]},
        'fs__strategy' : {"space" : ["variance", "rf_feature_importance"]},
        'fs__threshold': {"search" : "choice", "space" : [0.1, 0.2, 0.3]},
        'est__strategy' : {"space" : ["LightGBM"]},
        'est__max_depth' : {"search" : "choice", "space" : [5,6]},
        'est__subsample' : {"search" : "uniform", "space" : [0.6,0.9]}
        }

best_params = opt.optimise(space, data, max_evals = 5)

Which will give you the best hyperparameters in its output

Finally, it’s time to actually train and use the model to predict the popularity of a movie. This is can be done in just two lines with MLBox

p = Predictor()
predictions = p.fit_predict(best_params, data)

Barring, the bugs because of outdated code, it was quite easy to clean the data, train a fairly good model, and predict movie popularity. In a production system, one would definitely explore MLBox’s features more and perform extensive testing. Nevertheless, the library is quite good and does a decent enough job at automating machine learning.

Strengths and Limitations

MLBox has a lot of the advantages of AutoML, along with some distinct strengths:

  • Easy to use: MLBox has really high level APIs that abstract a lot of the underlying code.
  • Distributed Processing: MLBox works with large dataframes very quickly by taking advantage of multiprocessing and parallel programming
  • Powerful: MLBox can automate many of the tasks that are involved in building ML models.

While MLBox does offer all of these cool features, the repository is no longer maintained actively and has failed to keep up with updates to packages it depends on like scikit-learn, Pandas, and even Python. To get it working, you will have to look at the source code and remove or upgrade deprecated code yourself. Luckily, this is possible because it’s open source. Further, it is limited in its capabilities and seems to work well with standard or well formed datasets consisting of conventional data types. For e.g. you are not able to use bag-of-words of TfIdf vectorization.

In conclusion, it is a great library to get your feet wet with the world of AutoML, however, you’ll probably be able to find more up to date and robust AutoML frameworks online. MLBox can be a valuable tool in a production machine learning environment, but it is important to be aware of its strengths and limitations.
